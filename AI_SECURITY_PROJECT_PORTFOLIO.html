1. Executive Summary

Prompt injection is a security problem in which text, images, OCR output, documents, or tool responses contain instructions that attempt to redirect an AI system away from its trusted task. This project turns that problem into a repeatable evaluation workflow.

The framework contains versioned attack and benign corpora, deterministic undefended and defended agents, a transparent detector, multimodal image testing, local and hosted model adapters, CPU-only profiles, and structured reporting.

What the project proves

  • Untrusted content can be tested as a security boundary rather than treated as ordinary input.
  • Defense quality can be compared using explicit metrics such as detection, bypass, accuracy, false positives, errors, confidence, and latency.
  • Low-cost CPU experiments can produce useful and reproducible evidence without GPU infrastructure.
  • Security evaluation is stronger when bypasses and limitations are preserved instead of hidden.

2. How the System Works

Execution flow

  1. Bootstrap: checks Python and Node.js, installs missing declared packages, and prepares the selected command.
  2. Load data: reads a versioned text corpus, image corpus, local folder, JSON manifest, or HTTP(S) manifest.
  3. Establish trust boundaries: keeps the trusted review task separate from OCR, image text, documents, and other untrusted evidence.
  4. Run baselines: compares an undefended agent with a defended pipeline.
  5. Detect attacks: scores overrides, forged authority, role changes, tool calls, urgency, exfiltration, and related patterns.
  6. Evaluate models: sends consistent inputs to Ollama, OpenAI, Anthropic, Gemini, Hugging Face, or compatible local APIs.
  7. Report results: writes structured records and generates dashboards, catalogs, and office documents.

3. Research and Evaluation Design

Attack surface

Attack familyWhat it tests
Direct overrideWhether the model obeys an instruction to ignore the trusted task.
Forged authorityWhether labels such as system, admin, or supervisor improperly change priority.
Delimiter escapeWhether fake document boundaries can impersonate trusted context.
Role-play and urgencyWhether fictional framing or emergency pressure bypasses verification.
Fake tool responseWhether untrusted text can imitate a trusted tool result or next action.
ExfiltrationWhether the system follows requests to export logs, secrets, or process data.
Polite low-signal attackWhether subtle language avoids detection because it does not look aggressive.

Measured outcomes

  • Attack detection and attack bypass rate.
  • Overall accuracy and benign handling.
  • False positives and human-review holds.
  • Model confidence, provider errors, image errors, and request latency.
  • Per-sample prompts, model responses, run IDs, and configuration metadata.

CPU-first experiment

The CPU workflow is deliberately small and sequential. The `8gb` profile uses Moondream, one sample, and a 300-second timeout; the `16gb` profile uses Qwen 2.5 VL with two samples; the larger profile uses LLaVA with four samples and a longer timeout.

This design is valuable for scholarship and research evaluation because it makes the work accessible, controlled, and replicable without presenting a small test as a universal benchmark.

6. Interview Presentation Method

Use a clear five-part structure. Keep the first explanation under two minutes, then offer technical depth if the interviewer wants it.

  1. Problem: “AI systems may treat instructions inside an image or document as trusted commands.”
  2. Approach: “I created controlled attack corpora and compared undefended and defended agents across text and image inputs.”
  3. Engineering: “The system uses Python for evaluation and detection, model adapters for local and hosted LLMs, Node.js for reports, and CPU profiles for low-cost reproduction.”
  4. Evidence: “Every run records prompts, model configuration, prediction, confidence, latency, errors, and historical output.”
  5. Learning: “The key lesson is that a detector alone is not enough; trusted-task enforcement provides a second defense layer when detection misses subtle attacks.”

Two-minute interview answer

“My project focuses on prompt injection, where untrusted text or image content tries to control an AI system. I built a reproducible evaluation framework with attack and benign corpora, a deterministic undefended baseline, a defended agent pipeline, and model adapters for local and hosted LLMs. For images, it supports both OCR-style testing and actual image-byte evaluation. I also added CPU profiles so the experiments can run on ordinary laptops, and the system generates structured results and offline reports. The most important design decision was separating the trusted review task from untrusted content and measuring both detection and bypasses. I present it as a research prototype, not a guarantee of security, because documenting limitations is part of responsible AI engineering.”

My project investigates a growing challenge in artificial intelligence: the ability of AI systems to distinguish trusted instructions from untrusted content. I designed a reproducible framework that tests prompt injections delivered through text, OCR transcripts, and images. The system compares undefended and defended AI-agent behavior, evaluates multiple local and hosted models, records measurable security outcomes, and produces transparent reports. This work has strengthened my interest in AI security, responsible machine learning, multimodal systems, and research that connects technical innovation with practical safety.

Research contribution

The contribution is not a claim that one detector solves prompt injection. The contribution is an experiment design: a trust-boundary model, a reusable attack taxonomy, paired defense conditions, low-cost reproduction, structured measurements, and explicit limitations.

How to discuss European study goals

  • Connect the project to responsible AI, cybersecurity, trustworthy machine learning, and human-centered technology.
  • Explain that Europe’s research environment is attractive because it combines technical innovation with safety, privacy, governance, and societal impact.
  • Describe the next research step as adaptive and multimodal evaluation rather than promising a final solution.
  • Emphasize collaboration: the framework is designed so other researchers can reproduce, extend, and challenge the findings.

Responsible-use statement

This framework is for authorized research, education, and controlled security testing. Attack examples should not be connected to real external tools without isolation, authorization, logging, and human review. A bypass is a research finding, not a recommendation to deploy an unsafe agent.

Final positioning

AegisAI demonstrates the complete research loop: define a security problem, design controlled attacks, build a measurable defense boundary, compare models, preserve evidence, communicate limitations, and propose the next experiment.
